### What was verified sound, in detail

**1. `reinsert_member.rs` double-insert guard.** New line:
`require!(ctx.accounts.membership.issued_at < rr.epoch_started_at,
AyniError::NotInGoodStanding);`. Traced `Membership.issued_at` across the
codebase: it is stamped once, at `issue_provisional_membership.rs:48` or
`issue_membership.rs:61` (issuance time), **never** touched by
`confirm_admission`. So a member directly issued (`issue_membership`) during a
live epoch has `issued_at >= epoch_started_at` and is correctly rejected by
this new guard on any later `reinsert_member` call for the same commitment/
epoch — closing exactly the quorum-inflation DoS described. A member who was
provisional *before* the epoch began but is *confirmed* mid-epoch has an old
`issued_at` (predates `epoch_started_at`) so this guard alone would **not**
catch them — but `confirm_admission` mints an `EpochLeaf` PDA at
`["epochleaf", circle, epoch, commitment]` with Anchor `init`, and
`reinsert_member` requests the **identical** seeds with `init` for the same
PDA — Anchor's `init` fails on an already-initialized account, so the second
path is closed by account-collision, not by the timestamp guard. Read both
`#[derive(Accounts)]` blocks side by side; the seed byte sequences are
identical (`b"epochleaf"`, `circle.key()`, `epoch.to_le_bytes()`,
`membership.commitment`), confirming the collision is real and not merely
described as such. `EpochLeaf::SPACE` (89 = 8 disc + 32 + 8 + 32 + 8 + 1)
matches the struct's five fields exactly. This is architecturally sound.

**2. `confirm_admission.rs` — `recent_roots`/`epoch_leaf` now required.**
Confirmed the account context changed `recent_roots: Option<Box<Account<...>>>`
→ `recent_roots: Box<Account<...>>` (non-optional) and added a same-shape
`epoch_leaf` account with `init`. Confirmed `note_root.rs` is unaffected
(still `init_if_needed`, still permissionless) — so "the client cranks
`note_root` once" is achievable without a seat, matching the claim. Confirmed
`frontend/lib/admission.ts`'s `confirmAdmission()` now fetches (or creates)
`recentRoots` before calling the program and derives the matching
`epochLeaf` PDA with a hand-rolled little-endian u64 encoder — independently
re-derived the same PDA by hand from the seeds and confirmed it matches what
the Rust side expects. `frontend/app/admin/CircleAdmin.tsx` calls through
this same helper (not the raw program client), so the UI path is covered by
the fix automatically — no stale call site found anywhere in `frontend/`,
`indexer/`, or `scripts/`.

**3. IDL/build ground truth.** `anchor build` succeeded natively, 0 errors,
producing `target/deploy/ayni.so` at **1,315,736 bytes** — byte-identical to
the round's claimed fact. `frontend/lib/ayni.json`'s `confirm_admission` entry
has `args=['epoch']`, accounts include non-optional `recent_roots` and
`epoch_leaf` (`optional accounts: []` for both), matching the claim exactly.
`target/idl/ayni.json` and `frontend/lib/ayni.json` are byte-identical
(`diff` of pretty-printed JSON = empty) — the "IDL re-synced" claim holds.

**4. Frontend relay-route TOCTOU/budget fix.** Read `relay/route.ts` in full:
daily-tx-count increment now happens strictly after `validateRelayRequest`
returns `ok`; a new module-level `globalHits` array backs an unspoofable
60-req/min ceiling (keyed by nothing, so `X-Forwarded-For` rotation cannot
evade it, unlike the pre-existing per-IP bucket which is explicitly commented
as spoofable); `EST_COST` (6,000,000 lamports) is reserved into `outstanding`
*before* signing and released (success or failure, both code paths checked)
after reconciling to the real spend. This is a textbook reserve-then-reconcile
fix for the described race. No `console.*`/logger call exists in the diff.

**5. Frontend mailbox-route fixes.** `bundle` op: unchanged behavior, now
honestly commented as a bounded, accepted enrollment-oracle residual (matches
every prekey-directory design, including Signal's); throttled by the same new
global limiter. `put` op: hard `507` replaced with FIFO eviction (oldest
`mtimeMs` first, `existing.length - MAX_PER_BOX + 1` envelopes evicted) so a
flood cannot permanently block a victim's inbox — confirmed the eviction
targets old envelopes only, never leaks their plaintext (still opaque sealed
blobs), and races on `fs.stat` are handled (treats a raced-away file as
"newest" and skips it, rather than crashing). `frontend/lib/mailbox.ts`'s
fresh-device SPK epoch advance now takes `Math.max(localEpoch, dirEpoch) + 1`
instead of only `localEpoch + 1` — traced the server's monotonic-epoch
rejection rule (`route.ts:167-168`, `prev.epoch >= b.epoch` → 409) and
confirmed this client fix is exactly what's needed to self-heal a reset
device, with a graceful `.catch()` for a wallet with no existing bundle.

## Verdict rationale

Nothing that used to work broke. The program still builds cleanly and is
exactly the size and instruction count the team claimed; the new API surface
(`confirm_admission`'s extra `epoch` argument and two now-required accounts)
is consistently threaded through the Rust program, the regenerated IDL, and
every call site in the frontend and tests — I checked every place in the
repository that calls these two instructions and found no leftover call
using the old shape. Reading the two new guards side by side against how
membership timestamps actually get set, the fix genuinely closes the
double-insert hole two different ways for the two different ways a member
could have entered the tree, which is a more careful design than a single
check would have been. None of this touches anything the platform promises
to keep private — no new data is stored, no new field appears, nothing gets
logged, and the sponsor-recovery guarantees from Epic 11 are untouched.  What
keeps this from being a clean pass is that I could not turn on the actual
local test blockchain in this environment (a known, pre-existing limitation
of this sandbox, not a project problem), so the fix is verified by careful
reading rather than by watching it run and fail correctly against real data;
and the team's own regression tests for this fix only prove the "still
works normally" side, not the "the bad thing is now actually refused" side.
Two bookkeeping items — the project's own backlog document not yet updated
to match what shipped, and a growing pile of files that don't match the
project's code-formatting tool — round out the warnings. None of these three
things is a broken promise to a member; all three are close-before-next-round
housekeeping. Given a clean build, no privacy violation, and no proven
functional break, but with the fix's own teeth not yet demonstrated by an
executable test, the honest call is **pass, with warnings** — not a clean
pass, and not a failure.
